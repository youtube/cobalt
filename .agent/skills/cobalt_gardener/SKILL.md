# Cobalt Gardener Skill

> [!NOTE]
> An implementation plan is NOT necessary for executing this skill. You can proceed directly to execution.

This skill orchestrates the entire CI triage process for Cobalt. It retrieves results from available CI systems using retriever skills, and then performs a unified analysis of the failures.

## Prerequisites
- Prerequisites from all invoked skills.

## Detailed Steps

- [ ] **Clean Incoming Directory**

    Before starting, ensure the shared incoming directory is clean. Remove any old JSON files from `/tmp/cobalt_gardener_${USER}/incoming/`.

    ```bash
    rm -rf /tmp/cobalt_gardener_${USER}/incoming/*.json
    ```

    (Replace `${USER}` with your username).

- [ ] **Retrieve CI Results**

    Find all available skills that advertise or implement `cobalt gardener results gathering`.
    Invoke each of these skills to retrieve results from their respective CI systems.
    These skills will save their outputs (conforming to the unified schema) to the shared incoming directory `/tmp/cobalt_gardener_${USER}/incoming/`.

- [ ] **Triage Results**

    Invoke the `cobalt-ci-results-triage` skill.
    This will analyze all results in `/tmp/cobalt_gardener_${USER}/incoming/` and generate a unified report (`gardener_report.md` in your current working directory).

- [ ] **Verify and Report**

    Follow the verification steps in `cobalt-ci-results-triage` skill to verify the report and present it to the user.

## Report Formats

The triage process produces two types of reports: the raw script report generated by the analyzer, and the summarized triage report prepared by the agent for the user.

### Script Report

The `unified_analyzer.py` script produces a raw report listing the failing jobs in markdown format, grouped per branch, and providing a branch health report.

For each branch, it lists the health status (Healthy, Unhealthy, or Outdated Failures). Under each Unhealthy branch, it groups detailed failures by Run, listing the Run ID, SCM Event, and Source System (e.g. `[GITHUB]` or `[KOKORO]`). Under each Run, it lists the failed jobs with their Cached Log path, Job URL, and **Error Location(s)** pointing directly to the lines in the log where signatures matched, along with a helper command to slice the log around the error.

*   **Total Jobs Fetched**: 5
*   **Failed Jobs (Recent)**: 3
*   **Outdated Failed Runs**: 1

## Branch Health Report

### Branch: main (Unhealthy)
*   **Failed Jobs**: 3
*   **Outdated Failed Runs**: 1 (retrigger suggested)

## Detailed Branch Failures

### Branch: main

### Triage Report

The agent must summarize the raw script reports into a human-readable format for the user, interpreting the matching error locations to deduce the root cause.

The report must start with a single, unified list of suggested follow-up actions (e.g. retriggers for outdated runs/infra failures, investigations for new test failures/crashes, bugs to file) to give the user a clear path forward immediately.

Following the suggested actions, group the detailed issues per branch (ordered by release version descending, showing later releases first). For each branch, provide a health status and summarize the failures:
-   Main failure cause (e.g. Compilation error, Test failure, etc.) deduced from the matching log lines.
-   Number of failures and list of affected jobs.
-   Failure log lines.
-   Links to the CI runs.
-   Bug status (e.g. `Bug: NEW` or link to existing bug `Bug: b/12345`).

#### Example

### Suggested Actions

#### Retriggers
- Retrigger `main` [android_27 (ID: 444)](https://github.com/youtube/cobalt/actions/runs/444) (outdated nightly).

#### Investigations
- Investigate compilation error in `test.cc` on `main` [linux_compilation](https://github.com/youtube/cobalt/actions/runs/101/job/1).
- Investigate test failure on `main` [cobalt-linux-x64x11](https://sponge.corp.google.com/invocation?id=202).

### Detailed Branch Failures

*   **main** (Unhealthy) - 2 failed jobs

```
